# 2. Функциональные требования

Приоритеты относительно **целевого продукта**. Колонка «Статус в прототипе» относится к историческому UI-прототипу DocForge, а не к текущему приложению **docflow**.

Актуальное состояние реализации в Tauri-приложении: [../implemented-features.md](../implemented-features.md).

| Приоритет | Значение |
|-----------|----------|
| **Must** | Обязательно для целевого MVP |
| **Should** | Важно, но можно отложить |
| **Could** | Желательно / polish |
| **Planned** | Заявлено макетом / копирайтом, не в текущем React-прототипе |

## BR-4. AI-ассистент документации

| ID | Требование | Приоритет | Статус в прототипе |
|----|------------|-----------|--------------------|
| BR-4.1 | Чат «Вы» / «Ассистент» в контексте текущего метода | Must | Мок-чат |
| BR-4.2 | Контекст: `@method`, `@request.json`, `@response.json` | Must | Реализовано (UI) |
| BR-4.3 | Быстрые действия: «Сгенерировать из response.json», «Найти расхождения с кодом», «Уточнить формулировки», «Перевести на EN» | Must | Chips (эхо в чат) |
| BR-4.4 | Карточка diff с действием «Вставить» (и «Показать diff») | Must | Частично («Показать diff» без обработчика) |
| BR-4.5 | Сигнал готовности индекса: «AI-индекс актуален» | Should | Реализовано |
| BR-4.6 | Чек-лист задач ассистента: авто-создаваемый список шагов текущего плана (`todo`-инструмент), обновляемый по ходу выполнения, с возможностью вручную отменить все незавершённые пункты | Should | Реализовано |
| BR-4.7 | Артефакты: ассистент просит пользователя собрать структурированные данные, которых нет в репозитории (состав HTTP-запроса и ответа), карточкой в чате; пользователь заполняет их в визуальном конструкторе отдельной вкладкой и отправляет обратно. Артефакты сохраняются вне репозитория и доступны в любом чате; конструктор доступен и без запроса ассистента | Should | Реализовано |

**Бизнес-ценность:** диалог без потери фокуса; AI опирается на актуальные артефакты метода; типовые jobs одним кликом; контролируемое внесение правок; доверие к актуальности контекста.
